# Ruletrade-AI

Ruletrade-AI は、投資について**「そのとき何を考えていたか」**を残し、あとから自分の判断を振り返るための個人用アプリです。

文章や音声で考えを残すと、AIが投資仮説・前提・見直し条件などを整理します。時間が経って考えが変わったときには、現在の考えと過去の記録を比較できます。

## なぜ作ったか

投資を振り返るとき、株価が上がっていれば「買っておけばよかった」、下がっていれば「売っておけばよかった」と考えがちです。

でも、それは結果を知った後の評価です。

Ruletrade-AI では、利益が出たかどうかだけではなく、**その時点で持っていた情報から、なぜその判断をしたのか**を残します。

このアプリで目指す「良い投資判断」は、必ず利益につながった判断ではありません。  
**その時点の情報に基づいて考えられていて、仮説・前提・見直し条件が明確で、あとから自分で検証できる判断**です。

記録を残し、時間が経ってから振り返ることで、

- どんな前提を見落としやすいか
- どんなときに感情や値動きに引っ張られやすいか
- どの判断基準が繰り返し役に立ったか
- どの仮説やルールを修正した方がよいか

を少しずつ把握し、次の判断に反映できるようにすることを目指しています。

## 大事にしていること

### 結果ではなく、判断過程を残す

「儲かったから正しかった」「損をしたから間違っていた」だけで判断を評価しません。

何を根拠に考えたか、どんな前提を置いたか、何が起きたら考え直すつもりだったかを残し、その時点の情報と自分の基準に照らして振り返れるようにします。

### 過去を書き換えない

考えが変わっても、以前の判断は上書きしません。

新しい考えは新しい記録として追加し、**「以前はどう考えていて、なぜ今は違うのか」**を追えるようにしています。

### 記録する負担をできるだけ小さくする

記録が有益でも、入力が面倒なら続きません。

きれいに文章を整理してから入力するのではなく、思ったことをそのまま書いたり話したりし、AIに整理させることで入力の負担を減らします。

AIは投資判断を代わりに行うためではなく、**記録と振り返りの摩擦を減らすため**に使います。

### AIは判断者ではなく整理役

AIが行うのは、自由な入力の整理、過去の記録との比較、振り返りの補助までです。

「買うべきか」「売るべきか」を決めたり、注文を実行したりはしません。最終的な解釈と判断はユーザー自身が行います。

## できること

- **考えを記録する**：文章を入力するか、音声で話して記録します。音声は文字起こし後に修正できます。
- **AIで整理する**：自由な入力から、投資仮説・前提・見直し条件などを整理します。
- **保存前に確認する**：AIが整理した内容を確認・修正してから保存します。
- **銘柄ごとに振り返る**：購入、買い増し、売却の検討、仮説の更新、メモなどを時系列で読み返せます。
- **過去と今を比較する**：現在の考えと、その銘柄について過去に残した判断との差をAIが整理します。
- **売買の事実を残す**：数量・価格・日付などを記録し、売買履歴を確認できます。
- **振り返る時期を決める**：記録にレビュー日を設定し、期限が来た記録をアプリ上で確認できます。

## 基本的な使い方

1. ホーム画面で、今考えていることを書いたり話したりします。
2. AIが整理した内容を確認し、必要な箇所を修正して保存します。
3. 銘柄の詳細画面で、過去の判断や売買履歴を読み返します。
4. 考えが変わったときは新しい記録を追加するか、過去との比較を行い、自分の振り返りを残します。

入力した原文や音声の文字起こしと、AIが整理した内容は区別して保存します。新しい考えは以前の記録を上書きせず、別のタイムラインイベントとして追加されます。

## 技術構成

現在は**個人で使うMVP**として、必要以上にシステムを複雑にしないことを重視しています。

- Next.js / React / TypeScript
- SQLite
- Drizzle ORM
- Gemini
- Zod
- Vitest / Playwright

なぜこの構成にしたのか、データをどのように扱っているのか、AIとの境界をどう設計しているのかは [docs/architecture.md](docs/architecture.md) にまとめています。

## AIの利用範囲

文字起こし・内容の整理・比較を行う際は、処理対象の音声や文章、比較に必要な過去の記録が Google の AI サービスである Gemini に送信されます。

AIが整理した内容は、そのまま確定せず、保存前にユーザーが確認・修正します。

現在は個人利用を前提としており、ログインや複数ユーザー向けのアクセス制御はありません。また、レビュー期限のプッシュ通知やメール通知はありません。

## 自分の環境で起動する

Node.js 24、npm、Gemini APIキーが必要です。

```bash
npm install
cp .env.example .env.local
```

作成した `.env.local` に設定します。

| 設定名                    | 内容                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------ |
| `GEMINI_API_KEY`          | 自分のGemini APIキー                                                                 |
| `GEMINI_MODEL`            | 利用するGeminiモデル。初期値は `.env.example` を参照してください。                   |
| `RULETRADE_DATABASE_PATH` | 記録を保存するSQLiteデータベースの場所。初期値は `.data/ruletrade-mvp.sqlite` です。 |

`.env.local` や記録を保存したデータベースはGitにコミットしないでください。APIキーはサーバー側で使用します。

```bash
npm run dev
```

ブラウザーで [http://localhost:3000](http://localhost:3000) を開きます。
