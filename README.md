# Ruletrade-AI

Ruletrade-AI は、保有・取引・損益と売買判断の記録を残す、個人用の投資台帳アプリです。

考えたことは、まず原文のまま受け箱に保存できます。台帳の読み書きは画面からだけでなく、Muse 連携 API からも行えます。アプリ内蔵の AI（Gemini による文字起こし・内容整理・比較）は廃止対象で、記録の整理や補助は Muse 側へ移しています。

ライセンスは MIT です（[LICENSE](LICENSE)）。個人の記録用に作ったアプリなので、サポートはベストエフォートです。投資助言・売買推奨・注文実行をするアプリではありません。

## 試してみたい方へ

想定しているのは、自分のPCで自分専用に動かす使い方です。データは自分のPC内の SQLite ファイルにだけ保存され、作者のサーバーやデータとは一切つながりません。

一番簡単なのは Docker を使う方法です。Docker Desktop 等が入っていれば、Node.js を別途入れる必要はありません。

```bash
git clone https://github.com/RyoyaYahagi/Ruletrade-AI.git
cd Ruletrade-AI
docker compose up --build
```

ブラウザーで [http://localhost:3000](http://localhost:3000) を開きます。止めるときは `docker compose down`、記録したデータは Docker のボリュームに残ります（データごと消すときだけ `docker compose down -v`）。

Docker を使わない場合は、下の「自分の環境で起動する」（Node.js 24 が必要）を見てください。

試す前に知っておいてほしいこと:

- **APIキーがなくても台帳の基本機能は動きます。** 考えを原文のまま受け箱に保存する、売買を記録する、CSV を取り込む、JSON で入出力する、といった機能はキー不要です。音声入力・AIによる整理・過去との比較を使うときだけ、自分の Gemini API キーを `.env.local` に設定してください。
- **ログイン機能はありません。インターネットに公開しないでください。** あくまで自分のPCの localhost で使う前提です。公開すると、URLを知った人が記録をすべて見たり書き換えたりできます。
- **お問い合わせ機能は作者のリポジトリ宛てです。** アプリ内の「お問い合わせ・改善要望」は、作者の GitHub リポジトリの Issue に公開保存される仕組みです（設定方法は下の「お問い合わせの設定」）。個人情報や秘密情報を書かないでください。使いたくない場合は `GITHUB_FEEDBACK_TOKEN` を設定しなければ送信できません。
- **記録は自分のデータで置き換わります。** このリポジトリに作者の取引記録は含まれていません。まっさらな状態から始まります。
- **初回の起動・ビルドにはインターネット接続が必要です。** 依存パッケージの取得に加えて、画面のフォント（Google Fonts）をビルド時に取得します。オフライン環境では起動できません。
- **バックアップは JSON エクスポートで。** 「その他」画面から全記録を JSON で書き出せます。引っ越しや復元は JSON インポートで行えます。

## なぜ作ったか

投資では、買った理由も売った理由も、時間が経つと結果に引っ張られて曖昧になります。

Ruletrade-AI は、**その時点で持っていた情報から、なぜその判断をしたのか**と、売買の事実を、履歴の残る形で残すための台帳です。

個々の判断を訓練のように振り返るのではなく、保有全体をコア／サテライトの枠で管理し、割合が想定からずれていないかを確認できることを重視しています。

## 大事にしていること

### 事実と判断過程を残す

「儲かったから正しかった」「損をしたから間違っていた」だけで判断を評価しません。

何を根拠に考えたか、どんな前提を置いたか、何が起きたら考え直すつもりだったかを、売買の事実とあわせて残します。

### 過去を書き換えない

考えが変わったときは、以前の判断を上書きせずに新しい記録を追加します。入力の誤りなどを編集する場合も、変更前の内容は編集履歴に残ります。

新しい考えは新しい記録として追加し、**「以前はどう考えていて、なぜ今は違うのか」**を追えるようにしています。

### 枠で管理する

銘柄ごとにコア／サテライトの区分を持ち、変更履歴を残します。

割合は投入額ベースを主役として見て、時価ベースも併記します。サテライトの上限と警告線を決めておき、枠からずれたら気づけるようにします。

### AIはアプリの外へ

記録の整理や読み返しの補助は、Muse 連携 API 経由で Muse 側が行います。アプリ本体は台帳の役割に絞ります。

アプリ内蔵の AI（Gemini による文字起こし・内容整理・比較）は廃止対象で、順次取り外しています。移行中のあいだも、AIが整理した内容はそのまま確定せず、保存前にユーザーが確認・修正します。

「買うべきか」「売るべきか」を決めたり、注文を実行したりはしません。最終的な解釈と判断はユーザー自身が行います。

## できること

- **お問い合わせを送る**：「その他」の「お問い合わせ・改善要望」から文章または音声で送信できます。音声は文字起こしを確認・修正してから送信します。問い合わせはGitHub Issueに保存します。
- **考えを記録する**：銘柄を選ぶか未定のまま、原文を受け箱へ保存します。保存時にAIは呼び出しません。音声入力やAIによる整理は「整理フォームを開く」から利用できます。
- **AIで整理する（移行中）**：自由な入力から、投資仮説・前提・見直し条件などを整理します。アプリ内蔵AIは廃止対象で、今後はMuse連携経由に寄せていきます。
- **保存前に確認する**：AIが整理した内容を確認・修正してから保存します。
- **銘柄ごとに読み返す**：購入、買い増し、売却の検討、仮説の更新、メモなどを時系列で読み返せます。
- **過去と今の考えを比較する（移行中）**：現在の考えを入力すると、AIがその銘柄の過去の記録との違いを整理します。比較結果と自分の振り返りを保存できます。
- **売買の事実を残す**：数量・価格・日付などを記録し、売買履歴を確認できます。価格が不明な場合は空欄のまま保存できます。
- **CSVで売買履歴を取り込む**：「その他」から、楽天証券の日本株・米国株・投資信託、SBI証券・野村證券・マネックス証券の日本株CSVを取り込めます。取り込み前に内容や重複を確認できます。
- **保有銘柄の参考時価を見る**：参考価格、時価評価額、含み損益、通貨ごとの時価構成を確認できます。国内株式と米国株式の円換算合計を表示し、米国株式はドル表示と円表示を切り替えられます。
- **売却の実現損益を見る**：売却数量と売却直前の移動平均取得単価から計算します。手数料は差し引かず、円とドルを別々に集計します。価格などが不明な売却を含む通貨の合計は「不明」と表示します。
- **コア／サテライトの配分を確認する**：銘柄の詳細画面で区分を設定し、ポートフォリオで評価額に基づく割合と残り枠を確認できます。「その他」の「枠の設定」でサテライト上限と警告線を設定でき、警告線を超えると「今日」に表示されます。
- **振り返る時期を決める**：記録にレビュー日を設定できます。期限が来た記録は、アプリを開いたときに表示されます。
- **Museから読み書きする**：連携APIで台帳の読み取りと、判断・振り返りの確定保存、売買への判断紐付けができます。仕様は [docs/integration-api-v1.md](docs/integration-api-v1.md) を参照してください。
- **JSONでエクスポートする**：「その他」画面の「JSONをエクスポート」から、すべての銘柄・判断・売買履歴・振り返り・受け箱をダウンロードできます。原文、文字起こし、AIが整理した内容、記録同士の関連、コア／サテライトの区分と変更履歴、枠の設定を含みます。ファイルには形式のバージョン（`formatVersion`）と出力日時（`exportedAt`）も記録されます。
- **JSONから記録を復元する**：「その他」の「JSONをインポート」から、エクスポートした記録を取り込めます。既存の記録は上書きせず、同じ内容は追加しません。同じ識別子で内容が異なる場合は取り込みを中止します。枠の設定は、バックアップに含まれていればその値で復元します。

## 基本的な使い方

1. 「記録」で今考えていることを書き、必要なら銘柄を選んで「受け箱に保存」を押します。銘柄が未定でも保存でき、AIは呼び出しません。
2. 保存した原文は「今日」の受け箱で見返せます。音声入力やAIによる整理を使って記録したいときは、「記録」の「整理フォームを開く」を選び、整理結果を確認・修正して保存します。
3. 銘柄の詳細画面のタブで、過去の判断・売買履歴・振り返りを読み返します。
4. 振り返る時期が来た記録や、理由が残っていない売買は「今日」画面に表示されます。考えが変わったときは新しい記録を追加するか、「過去と比べる」から自分の振り返りを残します。

入力した原文や音声の文字起こしと、AIが整理した内容は区別して保存します。新しい考えは以前の記録を上書きせず、別のタイムラインイベントとして追加されます。

ポートフォリオの保有数量と参考取得額は売買履歴から計算します。株式の参考価格には Yahoo Finance の非公式なデータ取得手段を利用します。投資信託は銘柄の詳細画面でISINと投信協会コードを設定すると、投資信託協会の基準価額で評価できます。対応する米ドルMMFなどは固定の単価で評価します。これらは外部の参考価格であり、保有履歴の正本は売買記録です。

円換算では取得額と時価評価額に同じ現在の為替レートを使うため、含み損益に為替の損益は含みません。レートを取得できないときは米国株式を含む円換算合計を表示せず、米国株式はドルで表示します。

コア／サテライトの割合は米ドル建てを円に換算し、評価額の合計から計算します。この配分計算では価格を取得できない銘柄を取得金額で代用し、未分類の銘柄はサテライト側に数えます。コアの登録がない場合は残り枠を表示しません。

## AIの利用範囲

アプリ内蔵のAI（Geminiによる文字起こし・内容の整理・比較）は廃止対象で、記録の整理や補助はMuse連携APIの側へ移しています。移行が終わるまでは、現行の機能がそのまま残ります。

文字起こし・内容の整理・比較を行う際は、処理対象の音声や文章、比較に必要な過去の記録が Google の AI サービスである Gemini に送信されます。

AIが整理した内容は、そのまま確定せず、保存前にユーザーが確認・修正します。

現在は個人利用を前提としており、画面にはログインや複数ユーザー向けのアクセス制御はありません。Muse連携APIは読み取り用・書き込み用のトークンで保護します。APIの仕様は [docs/integration-api-v1.md](docs/integration-api-v1.md) を参照してください。また、レビュー期限のプッシュ通知やメール通知はありません。

## 自分の環境で起動する

Node.js 24とnpmが必要です。音声入力・AIによる整理・比較にはGemini APIキーも必要です。原文を受け箱に保存する際には使用しません。

```bash
git clone https://github.com/RyoyaYahagi/Ruletrade-AI.git
cd Ruletrade-AI
npm install
cp .env.example .env.local
```

作成した `.env.local` に設定します。

| 設定名                    | 内容                                                                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GEMINI_API_KEY`          | 自分のGemini APIキー                                                                                                                                       |
| `GEMINI_MODEL`            | 内容整理・比較に利用するGeminiモデル。初期値は `.env.example` を参照してください。                                                                         |
| `RULETRADE_DATABASE_PATH` | 記録を保存するSQLiteデータベースの場所。初期値は `.data/ruletrade-mvp.sqlite` です。                                                                       |
| `RULETRADE_READ_TOKEN`    | Muse 連携 API の読み取り用トークン。未設定なら読み取り API は無効です。                                                                                    |
| `RULETRADE_WRITE_TOKEN`   | Muse 連携 API の書き込み用トークン。読み取り用とは異なる値を設定します。判断・振り返りの確定保存と、売買への判断紐付けを提供します。下書きは保存しません。 |

`.env.local` や記録を保存したデータベースはGitにコミットしないでください。APIキーはサーバー側で使用します。

文字起こしには `gemini-3.5-transcribe` を使用します。音声をBase64形式でInteractions APIへ直接送信し、Files APIへのアップロードは行いません。[Googleの公式仕様](https://ai.google.dev/gemini-api/docs/transcribe)にある `smart` モードで「えー」「あのー」などのフィラーや繰り返しを除去し、言い直しや句読点も整えます。文字起こしの結果は、保存や送信の前に確認・修正できます。音声ファイルの上限は、Base64変換後のリクエストサイズを考慮して14 MiBです。

```bash
npm run dev
```

ブラウザーで [http://localhost:3000](http://localhost:3000) を開きます。

## お問い合わせの設定

問い合わせの保存先は `RyoyaYahagi/Ruletrade-AI` のGitHub Issueです。本文と分類のメタデータ（プログラムから読めるJSON）を保存します。アプリのSQLiteには問い合わせを保存しません。送信内容はGitHubリポジトリの閲覧者に公開されるため、個人情報や秘密情報を含めないでください。音声ファイルはGitHubへ送りません。

サーバー側の環境変数に次を設定します。`.env.local` の内容はコミットしないでください。

| 設定名                  | 用途                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| `GITHUB_FEEDBACK_TOKEN` | GitHub Issue作成に必須のトークン                                                                             |
| `JEV_GATEWAY_URL`       | Jevのローカル中継サービスのURL。例：`http://127.0.0.1:4789/v1/systemone`                                     |
| `JEV_GATEWAY_TOKEN`     | 中継サービスが認証を要求する場合のみ設定するトークン                                                         |
| `TYPESAFE_API_KEY`      | 中継サービスを使わずTypeSafeへ直接接続する場合のみ設定するAPIキー。この場合は `JEV_GATEWAY_URL` を空にします |

GitHubのFine-grained personal access token（対象と権限を限定できる個人用トークン）は、対象リポジトリを `RyoyaYahagi/Ruletrade-AI` だけにし、**Issues: Read and write** を許可してください。コードの書き込み権限は不要です。[GitHub公式のIssue作成API](https://docs.github.com/en/rest/issues/issues#create-an-issue)で必要な権限を確認できます。

JevはTypeSafeの問い合わせ分類用AIです。[公式HTTP API](https://docs.typesafe.ai/api)を既存の `fetch` から呼び出すため、依存パッケージは追加しません。カテゴリーと対象機能をChoice（選択肢）、重大度をScore（程度）、追加情報の必要性をNoul（はいの確率）で取得します。[Scoreの公式仕様](https://docs.typesafe.ai/primitives/score)に合わせ、0〜3の小数値を検証した後に最も近い整数へ丸めます。Noulは0〜1の範囲を検証し、0.5以上を `true` とします。分類結果は補助情報であり、ユーザーの最終入力が原文です。

中継サービスも直接接続用キーも未設定の場合、Jevの障害、3秒のタイムアウト、不正な応答の場合は、`category: other`、`area: unknown`、`severity: null`、`needsClarification: null`、`classificationSource: none` として送信します。Geminiで分類を代替しません。GitHubへの送信は10秒でタイムアウトします。ラベル付与には最大2秒待ちますが、失敗しても送信成功として扱います。

Issue作成に失敗したときは入力を残し、再送できます。通信切断やタイムアウトでは、GitHub側だけで作成が完了している可能性があります。再送の前にリポジトリのIssue一覧を確認すると重複を避けられます。自動再送は行いません。
