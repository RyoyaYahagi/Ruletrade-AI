# アーキテクチャ

Ruletrade-AI は、投資についてその時点で考えていたこと、判断、売買の事実、振り返りを追記型で保存する台帳です。アプリ本体は売買判断や注文を行わず、AI支援は Muse 側に寄せています。

## データモデル

Drizzle ORM を通して SQLite に保存します。

- `stocks`：銘柄情報
- `decisions`：原文、記録種別、任意の文字起こし・整理結果、レビュー日、出所
- `transactions`：売買区分、数量、価格、約定日時、判断記録への参照
- `reviews`：現在の入力、保存済みの要約・差分、本人の振り返り
- `captures`：受け箱の原文、銘柄ヒント、整理状態と判断への参照
- `integration_requests`：Muse 連携 API の冪等処理記録

CSV 取込の履歴と出所は `import_batches`、`import_batch_stocks`、`transaction_import_sources`、`import_changes` に保存します。

新しい判断や振り返りは新しいタイムラインイベントとして追加します。過去に保存された文字起こし・整理結果・比較結果のスキーマとデータは保持し、アプリ内のAI機能を削除する際に移行や削除は行いません。

## アプリケーションフロー

Next.js App Router で記録、銘柄詳細、振り返り、ポートフォリオ、売買履歴、データ管理を構成します。画面の保存処理には Server Actions を使います。アプリ内から外部AIサービスを呼び出しません。

記録では、原文を受け箱へそのまま保存するか、銘柄・記録種別・要約・整理点などを入力して判断記録として保存できます。文章はユーザー自身が記録・編集します。売買事実と振り返り日は必要に応じて記録できます。

振り返りでは対象銘柄の過去の判断を画面で読み返し、現在の考えと本人の振り返りを文章で保存します。過去のレビューに保存された要約・差分もそのまま表示・保持します。

Muse との連携は `/api/integration/v1` のスコープ別 API で行います。読み取りトークンでは参照だけ、書き込みトークンでは受け箱への原文保存、判断・振り返りの確定保存と売買への判断紐付けを許可します。API v1 の範囲と仕様は [integration-api-v1.md](integration-api-v1.md) を参照してください。

ブラウザー向け書き込み API は `Origin` と転送元のホスト名・ポートを照合し、他サイトからの送信を拒否します。この送信元確認はログイン認証ではありません。Muse 連携 API では別途 Bearer トークンのスコープを確認します。

## 技術選定

### Next.js + React + TypeScript

UI とサーバー側ロジックを1つのコードベースで管理します。画面の保存には Server Actions、Muse 連携には Route Handlers を使います。

### SQLite + Drizzle ORM

単一ユーザー向けアプリとしてローカルにデータを保存します。Drizzle は TypeScript と SQLite の間の永続化レイヤーです。原文と過去に保存された整理結果を別の項目として保持します。

### Zod

画面・API の入力と保存データを検証します。Muse 連携 API でも受信内容を検証してから保存します。

### Vitest + Playwright

Vitest はアプリケーションロジックを、Playwright は記録・台帳表示・振り返りの操作を確認します。

## 意図的に含めていないもの

- アプリ内AI、音声録音・文字起こし、自動整理・比較
- 売買判断や注文の実行
- Web 画面のログイン認証や複数ユーザーの所有権管理
- ベクトルデータベース、マルチエージェント構成、汎用公開 API

ローカルデータベースは `.data/ruletrade-mvp.sqlite` に保存します。`RULETRADE_DATABASE_PATH` で変更できます。
