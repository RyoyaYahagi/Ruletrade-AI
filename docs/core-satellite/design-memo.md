## 1. 背景と目的

個別株の判断基準は「綺麗に理想的に実行」はできない、というのが 2026-11-07 の議論の結論だった。その前提で行き着いた形がコア・サテライトである：

- コアはインデックスで固め、判断を介在させない
- サテライトは個別株。直感でやることも含めて「考える楽しさ」の置き場にする（投資は人生を豊かにするもので、目的ではない）
- 危ないのは2か所だけ：①勝ったサテライトの枠を広げたくなる ②負けたサテライトにコアから補充し続ける。どちらも銘柄選びの上手さとは無関係で、「枠の出入り口」の設計で止める話

本設計の目的は、この枠を Ruletrade-AI の台帳上で見える化し、維持しやすくすること。あわせて、将来の AI による自動投資でも、この枠がそのまま権限の境界（AI が触れるのはサテライト内だけ）として使える形にしておく。

## 2. 非目的（やらないこと）

- 枠を超えた買い付けの物理的な阻止（台帳は記録と表示の道具であり、証券口座の操作はしない。止める力の本丸は口座分離と送金ルールで、台帳の役割は可視化と警告まで）
- コア側の銘柄分析・振り返り（コアは「考えない」ことが設計。台帳に登録はするが、判断・振り返りの対象にはしない）
- サテライトの成績の自動判定や売買推奨（成績の検証は本人が数年単位で見る。台帳は数字を出すだけ）
- 損益表示の通貨合算（現行原則は維持。円換算するのは割合表示のためだけ、§4 D-済2）

## 3. 現状確認（2026-11-07 実測）

| 項目 | 確認内容 |
|---|---|
| 保有 | 21銘柄。すべて個別株で、ETF は金ETF（314A）のみ。**インデックス（投信・ETF）は台帳に1つもない** |
| 通貨 | JPY と USD が混在（USD は米国株7銘柄）。合計は通貨別が現行原則 |
| 銘柄の型 | `Stock` は id / ticker / name / market / marketCode / createdAt のみ。区分（コア／サテライト）の属性はない |
| 設定の置き場 | 窓口 API v1 に設定の概念はない。上限％・警告線％の置き場は新規に要る |
| 為替 | 取引の `settlement.exchangeRate`（約定時の記録）はあるが、現在レートの取得は窓口 API にない。既存の株価 quote 取得基盤が為替レートに対応しているかは**未確認**（CS-02 の最初の作業で確認する） |
| 期限・警告の仕組み | 振り返り期限と理由なし売買は `due` として既に窓口 API で読める。警告の surface 先として流用できる |

## 4. 決定事項（2026-11-07 本人決定）

1. **分母は台帳全体**：コアのインデックスは「銘柄」として台帳に登録する（登録作業自体は後日、本人が行う）。コア未登録の間、割合表示は実態（サテライトのみ）を注記つきで出す（CS-04）。
2. **割合は円換算で表示する**：割合表示に限って USD 資産を円換算する（参考表示、換算レートとその時点を併記）。損益などの他の表示は通貨別のまま合算しない。
3. **縛るのは投入額ベース**：サテライトの上限は「累計投入額 ÷ 全体の累計投入額」で判定する。値上がりで比率が膨らむのは自由（勝ち株を機械的に売らせない）。
4. **時価ベースは縛らず警告線だけ**：時価の割合が警告線を超えたら、利確してコアに戻すかの検討を促す表示／通知を出す。自動では何もしない。
5. **区分は銘柄の属性として持つ**：原則「買う前に決める」。変更は可能だが履歴を残す（負けた銘柄を後からコアへ逃がす抜け道を、見える形で塞ぐ）。

## 5. 未決定事項（推奨案つき）

### D1. 「投入額」の定義（売却した分を枠に戻すか）
- 推奨：**買付金額の累計（グロス）。売却では戻さない。**
- 理由：戻す方式だと「負けて売るほど枠が回復する」ため、歯止めとして緩い。グロスなら「直感に託した累計」がそのまま残り、検証（サテライトがインデックスに勝ったか）も単純。
- 割り切り：全売却した銘柄の投入分も累計に残り続ける。枠が窮屈になったら、それは「枠の見直し」として §5 D2 の上限変更で扱い、履歴に残す。

### D2. サテライト上限の数値（投入額ベース）
- 本人が決める数値。設計上は設定値（CS-03）として持ち、コードに埋めない。移行チャットの例示は2割だったが、確定ではない。

### D3. 警告線の数値（時価ベース）
- 本人が決める数値（設定値）。移行チャットの例示は4割。

### D4. 枠移動（コア→サテライトへの補充）の記録
- 推奨：**初版では専用の記録口を作らない。** 割合と残り枠は売買記録から自動計算され、「補充した」という事実は買い付け自体に表れる。意図を残したい場合は判断メモ（decision の note）で足りる。専用エンティティは CS-05 として切り出すが優先度は低く、保留のままでよい。

## 6. 設計の要点

- **表示の主役は「残り枠」**：割合（％）より「上限まであと何円サテライトに投入できるか」の方が、買い付けの瞬間の判断に直結する。ポートフォリオ画面の上部に、投入額ベースの割合＋残り枠を大きく、時価ベースの割合を小さく併記し、警告線超過時だけ時価側を目立たせる。
- **積み上げバー1本で足りる**：コア／サテライト／未分類の3区画。凝ったグラフは作らない。
- **未分類を許す**：既存21銘柄はすべて未分類で始まる。本人が順次分類する。未分類は割合計算ではサテライト側に倒して表示し、注記する（安全側：枠を広く見せない）。
- **換算レートは quote と同じ時点のものを使う**：株価が参考値であるのと同様、割合も参考値。レートの出所と時点を画面に小さく出す。
- **コア銘柄の価格が取れない場合**：投資信託など quote が取れない銘柄は、評価額を取得金額で代用し「評価額は取得金額で代用」と注記する（時価ベースの割合だけに影響する。投入額ベースは影響を受けない）。
- **AI 自動投資との接続**：将来 AI が執行に関わる場合、権限の境界はこの区分で引く（触れるのはサテライト内のみ、コアへの補充は人間の承認）。本設計では区分と集計までを作り、執行は扱わない。

CS-01（区分属性）→ CS-02（集計と円換算）→ CS-03（設定）→ CS-04（割合表示）→ CS-06（警告の surface）。CS-05（枠移動の記録）は任意・保留可。詳細は `issues.md`。
