## 設計の対象（4か所）

### 1. ポートフォリオ画面の割合表示（CS-04）
- 情報の階層：主役は「サテライト上限まであと何円投入できるか（残り枠）」と投入額ベースの割合。時価ベースの割合は副次。積み上げバー（コア／サテライト／未分類）
- 状態別の見せ方をすべて設計する：通常時／警告線超過時／上限未設定／コア未登録（割合がサテライトのみで計算されている注記）／円換算レート未取得／評価額を取得金額で代用した銘柄がある場合
- 注記類（換算レートと時点・「参考値」・各種の前提）を、常時出すか、畳むか、階層をどう付けるか

### 2. 区分（bucket）の表示と変更（CS-01）
- 保有一覧の行と銘柄詳細での区分の見せ方（バッジの有無・位置・言葉）
- `bucket-editor` の変更フロー：誤操作の防ぎ方（変更は履歴に残る前提で、確認を挟むか）、変更履歴の見せ方（置き場・量・畳み方）

### 3. 枠の設定フォーム（CS-03）
- 「その他」画面での置き方と、未設定状態の見せ方
- 入力時に「今の割合が何％で、上限をここに置くとどうなるか」が分かる助けが要るか

### 4. 今日画面の警告セクション（CS-06）
- 既存セクション（振り返り期限／理由が残っていない売買／未整理の受け箱）との並び順と優先度
- 警告のトーン：台帳全体は静かに事実を出す性格の中で、警告だけをどう目立たせるか（強さの段階）

## 設計の原則（制約）

- **データと計算ロジックには触らない**。設計対象は表示層（レイアウト、階層、文言、状態表現）だけ
- 既存のデザイン要素（globals.css のトークン、既存コンポーネント、#233 のモーション方針）を再利用し、新しい要素の追加は最小限に。追加する場合は理由を明記する
- 数字は事実として静かに出す。煽る表現・過剰な色使いはしない。強い表現は警告線超過の一点に絞る
- 文言は台帳の既存の言葉遣いに合わせる（既存画面のラベル・注記のトーンを実コードで確認すること）
- モバイル幅でも主役の数字と残り枠が崩れないこと
- 実コード・実画面で確認できないことは「未確認」と明記し、推測で断言しない

## 進め方と成果物

1. **現状確認**：対象 PR の UI 実装と既存画面のデザイン要素を実コードで読み、現状の課題（階層の弱さ、注記の埋没、状態表現の不足など）を箇所ごとに列挙する
2. **設計案**：対象4か所ごとに、レイアウト、情報階層、状態別の仕様、文言案を、実装者がそのまま実装できる粒度で書く。文章だけでなく、配置関係が分かるテキスト図（ワイヤーフレームの文字表現）を含める
3. **判断が要る点**：選択肢が割れる点は、選肢と推奨を併記して止める。勝手に確定しない
4. 成果物は `docs/core-satellite/design-proposal.md` に書き、最後にチャットで要約（現状課題の要点／設計案の骨子／判断が要る点の一覧）を報告する

実装（コード変更）はしない。設計案の承認後に別途依頼する。
