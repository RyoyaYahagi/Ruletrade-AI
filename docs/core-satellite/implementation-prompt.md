## 確定済みの方針（変更禁止）

- 分母は台帳全体。コアのインデックスは銘柄として後日登録される（登録作業は本依頼の範囲外。未登録の状態でも表示が壊れないこと）
- 円換算するのは割合表示のためだけ。他の表示（損益・保有一覧）は従来どおり通貨別で、換算・合算しない
- 縛るのは投入額ベース。時価ベースは警告線の表示だけに使う
- 区分（bucket）は銘柄の属性として持ち、変更履歴を残す
- 設計メモ §5 D1（投入額の定義）は **推奨案で確定として扱う**：買付金額の累計（グロス）、売却では戻さない。定義は集計モジュール内に閉じて実装し、後から変更できるようにしておく
- D2（上限％）・D3（警告線％）の数値は決めない。設定として保持・編集できる仕組みだけを作り、未設定（null）を許す

## ブランチと PR の進め方

- 各 Issue ごとに `issues.md` 記載の想定ブランチ名で切り、PR を作る（タイトルに CS-0X を含める）。main / develop へ直接コミットしない
- 起点は最新の `main`。ただし前提 Issue の PR が未マージの場合は、そのブランチをベースに積み上げ、PR の base もそのブランチに合わせる（PR 本文にベースを明記）
- 進行中の別作業 PR #233（`feature/ui-motion-inbox`、今日画面と受け箱の UI 変更）は未マージのまま存在する。CS の作業では触らない。CS-04 でポートフォリオ画面まわりに競合の恐れが出たら、無理に解決せず止めて報告する
- 各 PR で `npm run typecheck` / `npm run lint` / `npm run test` を通し、結果を PR 本文に書く
