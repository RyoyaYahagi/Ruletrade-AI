# Ruletrade-AI コア／サテライト Issue 分解

- 作成日: 2026-11-07
- 対応する設計メモ: `design-memo.md`（同フォルダ）
- 形式: 各 Issue は「目的 / スコープ（含む・含まない）/ 成果物 / 受け入れ条件 / テスト / 完了条件 / 依存」を明記し、そのまま GitHub Issue 化できる形にしてある
- 進め方: main / develop へ直接コミットしない。各 Issue ごとに小さなブランチ（`feature/csXX-<slug>`）と PR で進める。各 PR で `npm run typecheck` / `npm run lint` / `npm run test` を通す（E2E は該当 Issue に明記）
- 担当の目安: [App] = Ruletrade-AI 本体、[Muse] = Muse 側コネクタ・CLI
- 前提の決定: 設計メモ §4（分母は台帳全体／コアは銘柄登録／円換算は割合表示のみ／縛るのは投入額ベース／時価は警告線のみ／区分は銘柄属性＋変更履歴）
- 未決定事項: 設計メモ §5 の D1〜D4。D1 は推奨案（買付累計・売却で戻さない）で着手可だが、着手前に本人の最終確認を取ること。D2・D3 の数値は本人が設定画面で決める（Issue の完了条件には含めない）

## 依存関係の全体像

```
CS-01 区分属性 ──▶ CS-02 集計・円換算 ──┬─▶ CS-04 割合表示 ──▶ CS-06 警告の surface
CS-03 設定 ──────────────────────────────┘
CS-05 枠移動の記録（任意・保留可、依存なし）
```

## CS-01 [App] 銘柄への区分属性（bucket）と変更履歴

- **目的**: コア／サテライトの区分を銘柄に持たせ、変更の履歴を残す
- **スコープ（含む）**: `stocks` への `bucket` 列追加（値: `core` / `satellite` / `unclassified`、既定は `unclassified`、既存銘柄はすべて `unclassified` で移行）。区分変更の履歴テーブル（銘柄・変更前・変更後・変更日時。変更理由は任意の自由記述）。銘柄詳細画面と銘柄一覧での区分の表示・変更 UI。JSON エクスポート／インポートへの `bucket` と変更履歴の追加
- **スコープ（含まない）**: 割合の計算と表示（CS-02 / CS-04）、窓口 API への露出（必要になった時点で別途。CS-06 で due に触れる場合のみ再検討）
- **成果物**: スキーマ変更とマイグレーション、変更履歴テーブル、UI、エクスポート形式の拡張
- **受け入れ条件**:
  - マイグレーション後に既存の全画面・全 API（export 含む）が従来どおり動く
  - 区分を変更すると履歴に1行残り、画面から履歴を確認できる
  - 作業前に `.data` のバックアップを取り、復元手順を PR 説明に残す
- **テスト**: マイグレーション前後の export JSON の件数一致、区分変更と履歴記録の単体テスト
- **完了条件**: テスト合格＋ PR レビュー通過
- **依存**: なし（全 Issue の起点）
- **想定ブランチ**: `feature/cs01-stock-bucket`

## CS-02 [App] 区分ごとの集計（投入額・評価額）と円換算

- **目的**: 割合表示の材料になる数字を、既存の保有計算の部品を再利用して一箇所で計算する
- **スコープ（含む）**:
  - 最初の作業として、既存の株価 quote 取得基盤が USD/JPY の現在レート取得に使えるかを確認し、結果を PR 説明に記録する。使えない場合はレート取得の最小追加（出所は実装時に一次情報で確認できるものに限り、画面表示用であることを明記）
  - 区分ごとの集計：累計投入額（設計メモ §5 D1 の定義。確定までは「買付金額の累計・売却で戻さない」で実装）、現在評価額（円換算、換算レートと時点つき）。未分類はサテライト側に倒して集計し、その旨を戻り値に含める
  - quote が取れない銘柄（投資信託等）の評価額は取得金額で代用し、代用した銘柄があることを戻り値に含める
  - 集計は通貨別の既存表示には影響させない（換算するのはこの集計だけ）
- **スコープ（含まない）**: 画面表示（CS-04）、設定値の保持（CS-03）、成績の対インデックス比較
- **成果物**: 集計モジュール（区分別サマリを返す関数／内部 API）、為替レート取得、集計の単体テスト
- **受け入れ条件**:
  - 2026-11-07 時点の実データ（21銘柄・全て未分類）で、サテライト側の投入額・評価額が既存の保有計算（通貨別）と突き合わせて一致する（換算分を除く）
  - 換算レートが取得できない場合は、割合を出さず「レート未取得」と返せる（古いレートで誤魔化さない）
  - D1 の定義が変わった場合に、変更箇所が集計モジュール内に閉じている
- **テスト**: 通貨混在・quote 欠落・全売却済み銘柄を含むフィクスチャでの単体テスト
- **完了条件**: テスト合格＋ PR レビュー通過
- **依存**: CS-01
- **想定ブランチ**: `feature/cs02-bucket-aggregation`

## CS-03 [App] 枠の設定（サテライト上限％・警告線％）の保持と編集

- **目的**: 設計メモ §5 D2・D3 の数値を、コードに埋めず設定として持つ
- **スコープ（含む）**: 設定の保存先（アプリ設定として1箇所。新規テーブルまたは既存の設定の仕組みがあればそれに従う）と、「その他」画面等での編集 UI。項目は `satelliteCapPct`（投入額ベース上限）と `satelliteWarnPct`（時価ベース警告線）。未設定（null）を許し、未設定の間は CS-04 の表示と CS-06 の警告が「未設定」として振る舞う
- **スコープ（含まない）**: 数値そのものの決定（本人が画面で決める）、設定の窓口 API 露出
- **成果物**: 設定の保存と編集 UI
- **受け入れ条件**:
  - 設定を変更すると CS-04 の表示に即時反映される
  - 未設定に戻せる（null にできる）
  - JSON エクスポートに設定が含まれる
- **テスト**: 設定の保存・読込・未設定時の単体テスト
- **完了条件**: テスト合格＋ PR レビュー通過
- **依存**: なし（CS-04 が利用）
- **想定ブランチ**: `feature/cs03-bucket-settings`

## CS-04 [App] ポートフォリオ画面の割合表示

- **目的**: 枠の状態を、買い付けの判断に使える形でポートフォリオ画面の上部に大きく出す
- **スコープ（含む）**:
  - 主表示：投入額ベースのサテライト割合（％）と「上限まであと何円投入できるか」（残り枠、円）。上限未設定時は割合のみ＋「上限未設定」の注記
  - 副表示：時価ベースのサテライト割合（％）。警告線を超えた場合のみ目立つ表示（色・文言）に切り替える
  - コア／サテライト／未分類の積み上げバー（投入額ベース）
  - 注記の表示：円換算のレートと時点、「参考値」の明示。コアが1銘柄も登録されていない場合は「コア未登録のため、割合はサテライトのみで計算されています」の注記。評価額を取得金額で代用した銘柄がある場合はその注記
- **スコープ（含まない）**: 警告の通知（CS-06）、個別銘柄行のレイアウト変更、グラフの追加（バー1本まで）
- **成果物**: ポートフォリオ画面上部の割合表示コンポーネント
- **受け入れ条件**:
  - CS-02 の集計と表示が一致する（同じデータで数値が食い違わない）
  - コア未登録・上限未設定・レート未取得の3状態で、壊れた表示にならず注記が出る
  - 既存の通貨別表示（保有一覧・損益）は従来どおり
- **テスト**: 3状態を含む表示の単体テスト、ポートフォリオ画面の E2E（表示のみ）
- **完了条件**: テスト合格＋ PR レビュー通過＋本人が実画面で表示を確認
- **依存**: CS-02、CS-03
- **想定ブランチ**: `feature/cs04-portfolio-ratio`

## CS-05 [App] 枠移動の記録（任意・優先度低）

- **目的**: コアからサテライトへの補充など「枠の移動」の意図を、売買とは別に記録できるようにする
- **スコープ（含む）**: 枠移動の記録（方向：コア→サテライト／サテライト→コア、金額、日付、メモ）と一覧表示。割合・残り枠の計算には影響させない（計算は売買記録が正。設計メモ §5 D4）
- **スコープ（含まない）**: 計算への反映、窓口 API 露出
- **成果物**: 枠移動テーブルと記録・一覧 UI
- **受け入れ条件**: 記録の追加・表示ができる。計算結果が枠移動の有無で変わらない
- **テスト**: 記録の保存・読込の単体テスト
- **完了条件**: テスト合格＋ PR レビュー通過
- **依存**: なし。**本 Issue は保留でよい**（設計メモ §5 D4 の推奨は「初版では作らない」）。着手は本人の再指示があった場合のみ
- **想定ブランチ**: `feature/cs05-bucket-transfer`

## CS-06 [App][Muse] 警告線超過の surface（due 連携）

- **目的**: 時価ベースの割合が警告線を超えたら、振り返り期限と同じ置き場（今日画面／窓口 API の due）で気づけるようにする
- **スコープ（含む）**:
  - [App] 今日画面への警告の表示。窓口 API の due レスポンスへの警告の追加（既存の読み取り契約を壊さない形：追加フィールドとして足し、既存フィールドは変更しない）
  - [Muse] コネクタ CLI の due 出力で警告が読めることの確認（CLI 変更が要る場合は最小限）。CONNECTOR.md の Verified への追記
- **スコープ（含まない）**: 定期チェックやプッシュ通知（Muse 側の定期実行で拾うかは、本設計の完了後に別途判断）、警告への自動アクション
- **成果物**: 今日画面の警告表示、due レスポンス拡張、Muse 側の確認結果
- **受け入れ条件**:
  - 警告線を超えた状態を作ると、今日画面と due の両方に警告が出る。線以下では出ない
  - 既存の due 利用（振り返り期限・理由なし売買）が従来どおり動く
  - 警告線が未設定の間は警告を出さない
- **テスト**: 警告の境界（線の前後）の単体テスト、due の後方互換の確認
- **完了条件**: テスト合格＋ PR レビュー通過＋ Muse 側 due で警告が読めることを実データで確認
- **依存**: CS-04
- **想定ブランチ**: `feature/cs06-bucket-warning-due`
