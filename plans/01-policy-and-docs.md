# 01. 通知ポリシー改訂と ADR（価格・ニュース監視の境界定義）

## 目的

現行ドキュメントには「価格アラートはしない」（`docs/notifications.md`）、
「価格 API 連携はスコープ外」（`docs/portfolio.md`）と明記されている。
計画 02 以降はこの方針を変更するため、**コードを書く前に**ポリシー変更を文書として確定させる。

このリポジトリでは AI エージェントがドキュメントを根拠に実装判断をするため、
ドキュメントと実装が矛盾したままだと後続計画が誤った判断をする。この計画が最初に必要な理由である。

## 依存関係

なし。他のすべての計画より先に実施する。

## 最初に読むファイル

- `docs/notifications.md`（現行の通知ポリシー）
- `docs/portfolio.md`（現行のスコープ外リスト）
- `docs/product-philosophy.md`（製品哲学。この計画で変更しない）
- `docs/adr/` 配下の既存 ADR 1 つ（書式の参考にする）
- `src/lib/safety/prohibited-phrases.ts`（禁止語リストの現状）

## やらないこと

- コードの変更（このプランはドキュメントのみ。禁止語リストの追記だけ例外として行う）
- `docs/product-philosophy.md` の変更（「売買推奨をしない」原則は不変）

## 実装ステップ

### ステップ 1: ADR を新規作成

ファイル: `docs/adr/` 配下に既存の連番に続く番号で
`docs/adr/0XX-rule-condition-alerts-and-news-monitoring.md` を新規作成。

以下の内容を含めること（見出しは既存 ADR の書式に合わせる）:

1. **決定**: 次の 2 概念を区別する。
   - **市場タイミングアラート（引き続き禁止）**: 「株価が急騰しています」のような、
     ユーザーのルールと無関係に市場の動きを知らせて行動を促す通知。
   - **ルール条件成立通知（新たに許可）**: ユーザーが事前に承認した自分のルールに含まれる
     数値条件（例: 取得価格から -15%）が成立した事実を知らせ、ルールの確認を促す通知。
2. **理由**: 事前に決めたルールの執行支援は「感情に流されない取引」という製品目的そのものであり、
   売買推奨ではない。通知はユーザー自身の言葉（ルール）を引用する形でのみ発火する。
3. **通知文言の 3 要素規約**（plans/README.md の原則と同文）:
   事実 + ユーザー自身のルールへの参照 + 確認の促し。行動指示語の禁止。
4. **通知が満たすべき条件**:
   - 対象ルールが `approved` 状態であること（draft のルールでは通知しない）
   - 通知の本文にルール名（またはルールの条件文）を必ず含めること
   - 提示するアクションは「ルールを確認する」「仮説を維持して記録する」「ルールを見直す」の 3 種のみ
5. **ニュース通知の境界**: ニュース通知はユーザーが書いた投資仮説・破れ条件との照合結果のみを伝える。
   ニュース自体の評価（好材料/悪材料）を単独で伝えない。

### ステップ 2: `docs/notifications.md` を改訂

- 「What notifications do NOT do」の `provide price alerts` を次のように置き換える:
  - 禁止のまま: 市場タイミングアラート（ルールに紐づかない価格変動通知）
  - 許可: ルール条件成立通知（ADR 0XX 参照、という一文とリンクを付ける）
- 「Notification types」の表に、後続計画で追加する型を予約として追記する:

| type | purpose | 追加する計画 |
|------|---------|------------|
| `rule_price_condition_met` | 承認済みルールの価格条件が成立した | 06 |
| `price_data_stale` | 保有銘柄の価格が 3 営業日以上更新されていない | 02 |
| `portfolio_drift_exceeded` | ターゲット配分からの乖離が許容幅を超えた | 07 |
| `news_thesis_impact` | ニュースが投資仮説の前提に関係する可能性がある | 08 |
| `holistic_review_ready` | 月次総合レビューが作成された | 09 |
| `ai_budget_warning` | 月間 AI 利用額が上限の 80% に達した | 05 |

### ステップ 3: `docs/portfolio.md` を改訂

- 「Out of Scope」から次の 2 行を削除し、「Planned (see plans/)」節を新設して移動する:
  - `Price API integration`（→ plans/02）
  - `Automatic valuation updates`（→ plans/02）

    「リバランスの提案はしない。ターゲット配分からの乖離検知のみ行う（plans/07）」と注記する。

### ステップ 4: 禁止語リストの拡充

ファイル: `src/lib/safety/prohibited-phrases.ts`

既存の配列に、以下の語が未登録なら追加する（既にあればスキップ）:
「買い時」「売り時」「買うべき」「売るべき」「おすすめの銘柄」「今がチャンス」「乗り遅れ」。
追加した場合は既存のテスト（`tests/safety/` 配下）に検出テストを 1 ケースずつ追加する。

## テスト

- 禁止語を追加した場合のみ: `tests/safety/` の既存テストパターンに従い、
  追加語が `detectProhibitedPhrases`（`src/lib/safety/detect-prohibited-phrases.ts`）で
  検出されることを確認するテストを追加。
- `npm run typecheck && npm run lint && npm run test` が通ること。
